\section{Write Completion Tracking and BRESP Retirement}
\label{sec:write-completion}

Write completion tracking is implemented inside the write ROB instance
described in \S\ref{sec:rob}.

\subsection{Write ROB metadata}

Each write Metadata RAM entry is directly addressed by \texttt{ROB\_INDEX}
and contains:
\begin{itemize}[noitemsep]
  \item \texttt{exp\_pkts[6:0]}, the number of 64-B MC packets for the
        transaction (\texttt{1..64}, one per AXI data beat);
  \item \texttt{completion\_bitmap[63:0]}, initially zero;
  \item \texttt{resp\_status[1:0]}, initially \texttt{OKAY}; and
  \item \texttt{wr\_line\_base[25:0]} and \texttt{wr\_line\_count[6:0]}, the
        write's contiguous 64\,B line footprint, set at allocation from
        \texttt{\{AWADDR, AWLEN, AWSIZE, AWBURST\}}, not touched by
        completion, and freed with the entry. It is read only by the
        read-admission same-line hazard check (\S\ref{sec:samelinehaz}).
\end{itemize}

For each MC completion, the write ROB decodes \texttt{GLOBAL\_TAG} directly
(\texttt{[13:6]} = \texttt{ROB\_INDEX}, \texttt{[5:0]} =
\texttt{PACKET\_NUMBER}), sets \texttt{completion\_bitmap[PACKET\_NUMBER]},
and folds the packet status into \texttt{resp\_status} as
\texttt{resp\_status $\leftarrow$ max(resp\_status, map(status))} --- the
worst-of, precedence \texttt{DECERR} $>$ \texttt{SLVERR} $>$ \texttt{OKAY},
with \texttt{status} encoding \texttt{0}/\texttt{1}/\texttt{2} $=$
OK/SLVERR/DECERR (\S\ref{sec:cifmc}).  MC Core supplies exactly one
completion per accepted 64-B write packet (\S\ref{sec:cifmc-req}).
\texttt{exp\_pkts} is the count of 64-B MC packets the Burst Splitter
generates for the transaction; given the 64-B-beat contract
(\S\ref{sec:overview}) it equals \texttt{AWLEN + 1}.

\subsection{Ordered response and release}

The head index of each per-AXID Slot FIFO is eligible when
\texttt{completion\_bitmap} bits \texttt{[exp\_pkts-1:0]} are all set.  A
priority selection loads an eligible index into the write Retiring Register.  The write response
logic presents one BRESP for that transaction and holds it until
\texttt{bresp\_ready}.  Only on that acceptance does retirement pop the
selected Slot FIFO and return \texttt{ROB\_INDEX} to the write Free List.

This provides per-AXID AXI B ordering without coupling write release to read
traffic.
